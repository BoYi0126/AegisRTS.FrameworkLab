# 技術規格：比例、座標與輸出

## 1. Unity 世界尺度

- 固定比例：`1 Unity Unit = 1 公尺`。
- 所有模型以真實公尺製作，不可用匯入縮放補救錯誤尺寸。
- Unity Prefab 根物件的 Position 為 `(0,0,0)`、Rotation 為 `(0,0,0)`、Scale 為 `(1,1,1)`。
- 單位的導航與遊戲邏輯根節點固定在地面；視覺模型放在 `VisualRoot` 下。
- 現有原型的所有一般單位共用 NavMeshAgent：半徑 `0.38 m`、高度 `2.0 m`。換美術時先保持這個遊戲碰撞，騎兵與攻城兵器的較大碰撞需另開程式整合工作，不可只偷偷放大 Agent。

## 2. 座標與朝向

- Y 軸向上。
- Z 軸為模型正前方。
- X 軸為模型右方。
- 角色、馬匹與攻城兵器的樞紐在接地面的幾何中心。
- 建築樞紐在底面中心；城牆模組的樞紐可放在底面中心，但所有同類模組必須一致。
- 所有 Transform、旋轉與縮放在輸出前 Apply/Freeze。

## 3. 模型層級

單位建議層級：

```text
PF_Unit_Name
├─ GameplayRoot
├─ VisualRoot
│  ├─ SK_Name 或 SM_Name
│  ├─ TeamColorMesh（可合併，但需可替換材質）
│  └─ Socket_* / FX_*
├─ SelectionAnchor
├─ HealthBarAnchor
└─ GroundContact
```

建築建議層級：

```text
PF_Building_Name
├─ GameplayRoot
├─ VisualRoot
│  ├─ SM_Name
│  └─ TeamColorMesh
├─ SelectionAnchor
├─ HealthBarAnchor
├─ CapturePoint
└─ DamageSockets
```

美術交付可以不包含遊戲腳本，但必須提供上述空節點或清楚標記其座標。

## 4. 網格預算

以下為 LOD0 建議三角面數，不是要求把模型硬塞到上限：

| 資產 | LOD0 | LOD1 | LOD2 |
|---|---:|---:|---:|
| 一般雙足單位 | 2,500–6,000 | 1,000–2,500 | 250–700 |
| 指揮官／副官 | 4,000–10,000 | 1,500–4,000 | 400–1,000 |
| 騎兵（人馬合計） | 6,000–14,000 | 2,500–6,000 | 600–1,500 |
| 攻城兵器 | 5,000–12,000 | 2,000–5,000 | 500–1,200 |
| 小型建築 | 5,000–15,000 | 2,000–7,000 | 500–1,800 |
| 主堡／要塞 | 15,000–35,000 | 6,000–15,000 | 1,500–4,000 |
| 單一城牆／城門模組 | 2,000–12,000 | 800–5,000 | 200–1,200 |

- 單位至少提供 LOD0、LOD1；量產前再要求 LOD2。
- 建築輪廓比小雕花重要，幾何應集中在屋頂、門樓、垛口與入口。
- 不可保留不可見的內部面；不可有非流形幾何、重疊面或孤立頂點。

## 5. 材質與貼圖預算

- 一般單位：最多 2 個材質槽；第 1 個主材質，第 2 個陣營色／武器共用材質。
- 指揮官、騎兵、攻城兵器：最多 3 個材質槽。
- 小型建築：最多 3 個材質槽；主堡最多 4 個。
- 一般單位貼圖：1024×1024；指揮官可用 2048×2048。
- 建築：單棟 2048×2048，重複牆段優先共用 2048 atlas。
- 基本輸出：BaseColor、Normal、Mask/ORM；若是極簡低多邊形，可省略 Normal，但需先說明。
- 色彩空間：BaseColor 使用 sRGB；Normal、Mask/ORM 使用 Linear。
- 不得用 4K 貼圖掩蓋不合理 UV；同類兵種優先共用 atlas。
- UV 不可重疊，除非是明確鏡像或共用區域；Lightmap UV 需無重疊並保留 padding。

## 6. 骨架與蒙皮

- 雙足角色使用 Unity Humanoid 相容骨架；根骨命名 `Root`，骨盆 `Hips`。
- 騎兵使用 Generic：馬與騎手可同一骨架或父子骨架，但最終要有單一可控制根節點。
- 攻城兵器使用 Generic，以功能骨架控制輪子、弓臂、撞木或投射臂。
- 每頂點最多 4 個骨骼權重。
- Root Motion 關閉；位移由遊戲導航控制。
- 動畫期間腳底、輪子或車體不可讓根節點偏離地面超過 `0.05 m`。

## 7. 碰撞與導航

- 美術模型的精細 Mesh Collider 不可作為移動單位碰撞。
- 單位使用 Capsule/Box 等簡單代理；建築使用少量 Box Collider 組合。
- `VisualRoot` 可調整，但 `GameplayRoot` 不可跟著動畫位移。
- 單位外觀可略超出 0.38 m Agent 半徑，但常態姿勢不可超過各自文件的視覺包絡。
- 騎兵與攻城兵器若使用目標尺寸，程式端需在整合時新增依兵種設定的 Agent 半徑；在完成該工作前，先保留原型 0.38 m Agent 作功能驗證。

## 8. 檔案格式與命名

- 首選：`.fbx`；可同時提供 `.blend` 或 `.glb` 原始檔。
- 貼圖：`.png` 或 `.tga`，不要交付有損壓縮的 JPG 作正式材質。
- 命名：`CHR_` 角色、`VEH_` 騎乘／器械、`BLD_` 建築、`SM_` 靜態網格、`SK_` 骨架網格、`MAT_` 材質、`T_` 貼圖、`AN_` 動畫、`PF_` Prefab。
- 範例：`CHR_Infantry_A_v001.fbx`、`T_Infantry_A_BaseColor_1K.png`、`AN_Infantry_Attack_A.fbx`。
- 名稱只使用英文字母、數字與底線；版本使用三位數 `v001`。

## 9. Unity 匯入設定

- Scale Factor：`1`。
- Convert Units：開啟（若來源軟體正確以公尺輸出）。
- Read/Write：關閉，除非有明確執行期需求。
- Mesh Compression：先設 Off，驗收後依平台調整。
- Generate Colliders：關閉，改用指定的簡單碰撞體。
- 雙足 Animation Type：Humanoid；騎兵與器械：Generic。
- Import Constraints：關閉，除非有明確用途。
- 動畫 Root Transform Position/Rotation：Bake Into Pose，根位移不得驅動世界位置。
