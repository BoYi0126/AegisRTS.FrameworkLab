# 畫面規格：解析度、相機與安全區

## 1. 核心原則

遊戲畫面必須填滿玩家當前視窗，而不是把 3D 世界做成固定像素大小。3D 資產使用公尺；Camera 與 UI 依 `Screen.width`、`Screen.height` 自動適配。

- Camera Viewport Rect 固定為 `(0,0,1,1)`，填滿整個遊戲視窗。
- 不使用固定 960×540 RenderTexture 放大到視窗。
- 主要比例為 16:9；16:10 與 21:9 必須能顯示，不可裁掉操作按鈕。
- 最低支援與驗收解析度：`960×540`。
- UI 設計基準：`1920×1080`。
- 常用驗收：960×540、1280×720、1920×1080、2560×1440。
- Windows Player 啟動時固定使用 `FullScreenWindow`（無邊框全螢幕），解析度取目前主顯示器 `Display.main.systemWidth × systemHeight`；若顯示器 API 未回報有效尺寸，才退回 `Screen.currentResolution`。Unity Editor 的 Game View 不強制切換全螢幕。
- 全螢幕與 Editor Game View 都使用目前 `Screen.width × Screen.height` 重新排版；不另外拉伸 3D 世界或使用固定像素 RenderTexture。

## 2. 現行 RTS 相機契約

目前原型使用透視相機：

- 垂直 FOV：Unity 預設 `60°`；正式整合應明確鎖定為 60°。
- Pitch：`55°`。
- Yaw：`0°`。
- 預設相機距離：`31 m`。
- Zoom 範圍：`2.5–40 m`；`2.5–4 m` 是人工檢查模型、骨架與動畫用的近距視角，正常 RTS 遊玩仍以 `8–40 m` 為主。最近距離會自動把 Pitch 從 `55°` 漸變到 `38°` 並聚焦角色身體；Yaw 仍鎖定，玩家不能自由旋轉相機。
- Zoom 輸入：滑鼠滾輪向上拉近、向下拉遠；預設靈敏度為原基準的 `×3`，`+`／數字鍵盤 `+` 每次提高一級，`-`／數字鍵盤 `-` 每次降低一級，可調 `×1～×6`。Unity Input System 將 `<Mouse>/scroll` 與速度鍵交由 `UnityRtsInputAdapter` 傳給 `RtsCameraController`，最小／最大距離仍由 `RtsCameraRigModel` clamp。
- 地圖移動邊界：X、Z 各 `-45–45 m`。

所有資產的可讀性截圖使用 55° Pitch、60° FOV、31 m 距離。另以 40 m 最遠距離檢查兵種輪廓，2.5 m／38° 自動 inspection Pitch 檢查建模、骨架、破面與貼圖。

## 3. 預期螢幕尺寸

在 60° 垂直 FOV、31 m 距離下，1.8 m 高的一般士兵在 960×540 約為 27 px 高；在 1920×1080 約為 54 px 高。實際值會因士兵與相機焦點距離而略有差異。

因此：

- 兵種主要輪廓差異必須至少佔角色寬度的 20%。
- 關鍵武器在 960×540 預設視角的可見厚度至少 2 px；換算模型厚度建議不低於 `0.06 m`。
- 不依靠臉部、手指、腰帶紋樣來分辨兵種。
- 弓、長矛、盾、旗幟、馬匹、撞木等大形狀才是第一辨識層。
- 指揮官比一般士兵高 15–20%，並有披風、肩甲或背旗等第二輪廓。

## 4. UI 比例與安全區

正式 Canvas 建議：

- Canvas Scaler：`Scale With Screen Size`。
- Reference Resolution：`1920×1080`。
- Screen Match Mode：`Match Width Or Height`。
- Match：`0.5`。
- UI 必須使用 Anchor，不可只寫死 1920×1080 的絕對座標。

HUD 安全規則：

- 視窗四邊至少保留 2% 安全邊距。
- 主要操作按鈕不可超出 X=`3–97%`、Y=`4–96%`。
- 上方狀態／目標 HUD 以畫面高度 18% 為上限。
- 下方指揮面板以畫面高度 30% 為上限；960×540 時目標高度約 150–165 px。
- 世界中最重要的戰鬥事件，盡量發生在 X=`8–92%`、Y=`20–68%` 的視覺安全區。
- 血條、名稱與世界提示不可被下方指揮面板遮住；超出安全區時應隱藏、偏移或改用邊緣指示。

目前原型仍使用 IMGUI，已依 `Screen.width/height` 排版；這份規格同時是日後改成 Canvas/UI Toolkit 的目標，不代表現在已完成 UI 重構。

## 5. 寬螢幕與窄視窗行為

- 16:9：完整基準畫面。
- 16:10：維持垂直 FOV，左右視野略窄；HUD 不可重疊。
- 21:9：維持垂直 FOV，增加左右世界視野；不可拉伸模型。
- 小於 960×540：允許進入緊湊 HUD，但不列為正式支援；必須顯示可理解的最小尺寸警告或自動縮排。
- 視窗尺寸改變時，在下一幀重新計算 UI；不可要求重啟遊戲。

## 6. 美術驗收截圖

每個單位與建築至少提供：

1. 960×540、相機距離 31 m 的正常遊戲截圖。
2. 1920×1080、相機距離 31 m 的正常遊戲截圖。
3. 960×540、相機距離 40 m 的最遠辨識截圖。
4. 960×540、相機距離 2.5 m 的最近檢查截圖。
5. 我方藍、敵方紅、灰階輪廓三種比較圖。

通過條件：不看文字標籤，測試者能在 2 秒內分辨角色類型；建築入口、城門開口與可攻擊核心清楚可見。

## 7. 解析度與資產責任邊界

- 「畫面剛好符合視窗」是 Camera、Display Mode、UI Anchor 與 Canvas Scaler 的責任。
- 「單位看起來太小」先調相機距離、FOV 或辨識輪廓，不可把全世界模型任意放大。
- 「UI 擋住單位」調 HUD 安全區或世界提示位置，不可把建築比例縮壞。
- 美術 AI 只需依公尺尺寸與驗收截圖交付；整合 AI／程式負責解析度適配。
