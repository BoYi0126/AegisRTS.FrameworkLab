# 美術製作批次與目前整合缺口

## 1. 現況結論

目前遊戲可以運作。步兵已完成 Prototype L3：Unity Humanoid、LOD0／LOD1／LOD2、五段動畫、Team Color、anchors 與 Runtime Prefab 都已接入；其他單位、英雄與主要建築仍是 Primitive／Placeholder。這批文件定義後續資產要做成什麼、要多大、怎麼交付。

解析度現況：

- Windows Player 設定為 `fullscreenMode: 1` 與 `defaultIsNativeResolution: 1`，全螢幕模式會以目前顯示器原生解析度顯示。
- Camera 使用完整 Viewport，現行 IMGUI 以 `Screen.width/Screen.height` 排版。
- Windows 視窗模式目前 `resizableWindow: 0`；若玩家需要自由拖曳調整視窗，仍需另開程式／PlayerSettings 任務。
- 預設 Windows 欄位仍是 1024×768，但先前測試 Build 以 960×540 執行；規格要求未來正式支援最低 960×540、基準 1920×1080。
- 相機垂直 FOV 目前依 Unity 預設值，尚未在程式中明確鎖定 60°。

因此「畫面跟目前全螢幕解析度一致」已有基礎；「所有任意視窗縮放都完整驗收」尚未完成，不應只靠美術資產解決。

- 步兵以外 Prefab 的 `HealthBarAnchor` 整合；步兵已使用 Prefab anchor。
- 正式 Projectile Prefab 與弓兵放箭視覺串接。
- 城門破壞／修復正式動畫與傷痕表現。
- 全兵種隊伍色 Shader／MaterialPropertyBlock 標準化；步兵流程已完成。
- 步兵以外的 LODGroup，以及跨兵種批次效能與大量單位實機測試。
- Canvas/UI Toolkit 的正式響應式 UI 重構。
- 16:10、21:9、多螢幕、DPI 與任意可調視窗驗收。

## 7. 每批整合流程

1. 只做 L1：比對尺寸圖、黑剪影、藍紅換色。
2. 由人類確認概念，不合格先在圖階段退件。
3. 進 L2：Unity Graybox 場景中以 Scale 1 放入，比較 Footprint。
4. 在 960×540／1920×1080、Zoom 8／31／40 截圖驗收。
5. 進 L3：補骨架、動畫、Socket、LOD。
6. 程式串接 Selection、Health、Projectile、Gate State 與 Team Color。
7. 大量單位效能測試與 Windows Build 實機驗收。
8. 更新 `DevelopmentProgress.md`，記錄完成、未完成、授權與來源。

步兵目前已完成 Prototype L3 Unity 整合，實際成果依 `Unit_03_步兵_L3骨架動畫交付規格.md` 驗收；商用發布仍必須確認原 v001 來源權利並通過人工動畫品質審查。弓兵應沿用相同來源／Runtime 分流、Humanoid、事件與驗收流程。

弓兵也已於 2026-08-13 完成 Prototype L3 Unity 整合：`PF_Unit_Archer`、Humanoid 五段動畫、LOD0／1／2、Runtime Team Color、`Socket_Projectile`、`ProjectileRelease`、獨立 Z+ 箭矢與 pooled flight／impact 均已接入。完整證據與仍未達 production-ready 的項目見 `Unit_04_弓兵_L3實作交付與驗收.md`。Batch A 下一個建議項目改為指揮官或城門，不再把弓兵列為 placeholder 缺口。

第一個美術 Milestone 不需要完整世界觀。只要完成步兵、弓兵、指揮官、城門、城牆、要塞主堡，以及箭矢色塊／低模，就應能在現有 Prototype 中看到：

- 框選單位後立刻分辨兵種。
- 弓兵拉弓並生成獨立箭矢。
- 步兵與攻城衝車的攻擊方向清楚。
- 城門破壞後入口清楚打開。
- 攻入內院後，主堡是明確的占領目標。
